# Security-key emulator: next-session handoff

This is the software YubiKey-compatibility project requested for the YubiKey 5C Nano firmware 5.7.4 profile. The goal is **full externally observable compatibility** across both macOS and Linux, including recognition as a security-key device. The goal remains **active**. `complete_yubikey_equivalence` must stay `false` until every required behavior is independently verified. The repository used as the initial reference is `madeye/swpasskey` commit `59f08259202028888934597513515fc3cb8ca8c9` (MIT); the delivered implementation is much larger than that original FIDO project.

## What exists

The implementation covers CTAPHID, CTAP2.1, U2F, credential/PIN/UV lifecycle, OTP/YubiOTP/HMAC challenge-response, PIV, OpenPGP, OATH, YubiHSM Auth, Security Domain SCP03/SCP11 paths, FIDO and OTP HID, CCID/IFD, and a Linux FunctionFS composite USB gadget in an isolated guest. It includes own encrypted software state, software-only touch and power models, SDK-facing device and card transports, protocol regression fixtures, Mac/Linux native C++ builds, unmodified SDK checks, and no-network Linux `dummy_hcd` USB guest checks. Exact scopes and exceptions are in the status/matrix JSON; do not infer full parity from a passing smoke test.

Version 0.64 adds three specific boundaries to the 0.63 release: the same CTAPHID CID cannot interleave PING/WINK with an active CBOR transaction; symmetric YubiHSM Auth GET CHALLENGE creates its random host value without demanding touch while CALCULATE still demands touch; malformed SCP03 INITIALIZE UPDATE `Le` is rejected before consuming a retry or resetting the session. The previous 0.63 release guards PIV GENERAL AUTHENTICATE `Le` before PIN_ALWAYS authorization or key use. Each change has an isolated before/after patch and evidence directory. The 0.64 integrated evidence must show Mac/Linux C++ 140 cases and 13,748 assertions each, the main 5,889 Python checks plus 140 C++ cases (6,029 checks), independent Linux python-fido2 82 checks, Mac/Linux private socket/direct IFD checks, and a 12-marker no-NIC USB guest run. Read the actual report before quoting these as completed.

## Critical boundaries and remaining work

- No physical 5C Nano 5.7.4 command-by-command differential has established identical malformed-command status, error precedence, timing, state changes, or edge-case tolerance. Current patches are specification- and SDK-aligned software-model fixes with explicit unmeasured physical behavior.
- There is no physical touch sensor or hardware-backed power-cycle timing. The software presence/press/reboot model and fixed guest timing are observable approximations.
- The macOS modified runtime has **not** registered a composite FIDO/OTP/CCID virtual device under the user's identity. Apple Developer signing and the restricted `com.apple.developer.hid.virtual.device` entitlement/provisioning profile are not available. The original author's signed binary does not sign a modified application.
- Linux USB tests use an owned no-NIC QEMU `dummy_hcd`/FunctionFS guest. Other UDCs, production USB controllers, external macOS/Windows/Linux host hardware, and exact wire electrical/timing behavior remain unverified. GadgetFS has known unreliable feature operations; the verified primary path is FunctionFS.
- Manufacturer attestation chains, certified hardware identity, secure-element resistance, unextractable secrets, and a physical button cannot be cloned by software. A matching public USB ID, reader name, or protocol response does not confer manufacturer trust. Own software identities and fresh test credentials are used.
- Some published documentation and historical upstream README paragraphs describe the original signed upstream app or old checkpoints. For this fork's current claims, use `implementation-status.json`, `compatibility-matrix.json`, and the versioned evidence. `source/README.md` is marked historical upstream documentation.

The real inserted YubiKey, its credentials/configuration, host HID/USB/PCSC, Keychain, keyboard, Secure Enclave, and host kernel have **not** been touched during this work. Maintain this boundary unless the user explicitly changes it. Private Unix sockets, direct test IFD libraries, local software state, no-NIC containers, and owned dummy_hcd QEMU guests are the established safe routes.
