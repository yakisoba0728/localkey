# OATH catalog status (lk-oath)

One line per bullet of the `## OATH` section of `reference/BEHAVIOR_CATALOG.md`.
Test names refer to `crates/lk-oath`: `tests/protocol.rs`, `tests/vectors.rs`,
`tests/interop.rs`, `tests/fuzz.rs`, and the unit tests in `src/` (`tests::`,
`state::tests::`, `credential::tests::`, `request::tests::`).

Counting convention: each bullet has exactly one label, the first word after the colon.

- `tested`: the named tests pass and exercise everything in the bullet that a single
  `CardApplet` can show. Notes in parentheses record model-policy choices made where
  the catalog and YKOATH leave a status or detail open. They do not change the label.
- `intentional difference`: the engine deliberately behaves or verifies differently
  from what the bullet (or the public YKOATH wording it rests on) says. The reason
  comes first, then the tests that cover what does apply.
- `deferred`: something the bullet needs is missing.

Totals for the `## OATH` section: 17 tested, 3 intentional differences, 0 deferred.
With the related rows below, `tools/catalog_status.py` counts 22 tested, 3 intentional
differences, 0 deferred.

- Factory salt (device id, SELECT tag `71`) stable across restarts: tested: `restart_and_unreadable_state`, `rejected_factory_save_is_stored_by_the_first_commit`, `device_id_is_stable_across_restarts`. `Oath::new(None, ..)` persists the factory state at once (`docs/CONTRACTS.md` "Constructors may persist"; requirement of the final review, which replaces the earlier "persisted only at the first mutating command"). Reason: yubikit and yubikit-android derive `device_id = base64(SHA-256(salt)[..16])`, and ykman (`oath access remember`, `info`, `reset`) and Yubico Authenticator key remembered passwords by it, so a salt that changed at each start would forget them. A rejected save is not reported; lk-device saves a rejected constructor state again before its next input, and every later commit writes the whole state. A record that exists but does not decode is factory state and is not overwritten at construction (model policy: opening never destroys a record, `docs/DESIGN.md` §7); lk-device passes `None` for a record it cannot open and shields it from constructor saves.

## Host request shapes

`tests/interop.rs` sends what the public host software sends, byte for byte, and checks the status words it interprets. Sources: yubikit (`yubikit/oath.py`, `yubikit/core/smartcard/__init__.py`, used by ykman and the Yubico Authenticator desktop helper), yubikit-android `OathSession.java`, ykman `ykman/_cli/oath.py`, Yubico Authenticator `helper/helper/oath.py`.

- yubikit over USB uses the extended APDU format and no Le: data-less commands are the 4-byte case 1, the rest case 3E; `61xx` is followed with `00 A5 00 00`: `yubikit_usb_session_in_extended_format`, `yubikit_extended_long_responses_continue_with_send_remaining`.
- yubikit in the short format (NFC, `force_short`) appends `00` to a command without data or Le (case 2S): `yubikit_short_format_dataless_commands`. The extended data-less form `.. 00 00 00` of `docs/CONTRACTS.md` is accepted too: `extended_dataless_form_is_accepted`.
- `put_credential`: secret zero-padded to 14 bytes, touch as the raw pair `78 02`, IMF `7A 04` only for an HOTP counter above 0 (ykman refuses a counter on TOTP): `yubikit_usb_session_in_extended_format`, `yubikit_android_shapes`.
- `calculate_all` `00 A4 00 01` with the 8-byte step `timestamp // 30`; yubikit infers HOTP only from `77` and touch from `7C`, so an HOTP credential with touch is `77`: `yubikit_usb_session_in_extended_format`, `calculate_all_mixed_types_touch_and_only_increasing`.
- `calculate_code` P2 `01`: `74 00` for HOTP (yubikit), eight zero bytes for HOTP (yubikit-android), the step for the account's period for TOTP; `calculate` P2 `00` returns `75 digits || HMAC`: `yubikit_usb_session_in_extended_format`, `yubikit_android_shapes`.
- `rename_credential` (firmware 5.3.1+), `delete_credential`, `set_key` (`73 21||key 74 challenge 75 HMAC-SHA1`, same session keeps working), `validate`, `unset_key` (`73 00`), `reset` (`00 04 DE AD`, then a new SELECT with a new salt): `yubikit_usb_session_in_extended_format`, `yubikit_android_shapes`.
- Status words: `6A80` from VALIDATE is a wrong password (ykman, Authenticator, yubikit-android); `6982` from a touch CALCULATE is a touch timeout (ykman "Touch account timed out!", Authenticator after 5 s) and from other credential commands "authentication required" (Authenticator); `6A84` from PUT is "no space" (ykman); `6A80` from PUT or RENAME is shown as "Issuer/name too long" (Authenticator): `status_words_the_hosts_interpret`.
- Interop note, not modelled further: ykman answers a `6581` from CALCULATE ALL with `delete_broken_credential` (a workaround for a firmware fault): it calculates each TOTP credential without touch up to five times and deletes the one credential that answers `6581` every time. lk-oath answers `6581` only when the store fails (`docs/CONTRACTS.md`); under a failing store only an "only increasing" credential (whose raised challenge must be saved) answers `6581` to that probe, and the DELETE that follows needs a save as well, so it fails unless the store recovers in between.
