# Open compatibility gaps and next gates

The objective is complete external compatibility with a YubiKey 5C Nano 5.7.4 in both Linux and macOS device contexts. The project is **in progress**. This list highlights the highest-impact gaps; the exhaustive release-by-release inventory is `../implementation-status.json` (`remaining_work` and `inherent_differences`) and `../compatibility-matrix.json` (criteria). Treat a missing test as unverified, even if source code exists.

| Gap | Current evidence | Completion gate |
| --- | --- | --- |
| Exact 5.7.4 command behavior | Public read-only profile bytes and specifications, SDK interoperability, software A/B tests | A deliberately authorized physical differential corpus covering valid/malformed APDUs, CTAP/HID and OTP flows, errors, state transitions, restarts and timing; protect existing real credentials/settings. No such corpus has been run. |
| macOS recognition of the **modified** composite device | Source and isolated macOS private socket/IFD/HID path tests; historical upstream signed app claims are separate | Apple-granted restricted virtual HID entitlement, the user's valid Developer signing/profile, installed modified bundle and unmodified macOS client tests against that registered device. The required signing environment is not available. |
| Production USB transport and external hosts | Own no-NIC Linux QEMU `dummy_hcd` FunctionFS guest, stock guest HID/CCID/OTP clients, captured public descriptor comparison | Test real supported USB device controller(s), macOS/Linux/Windows external hosts and re-enumeration/power/error behavior, with scope-specific hardware and host authorization. GadgetFS feature operations remain unreliable; the primary validated guest path is FunctionFS. |
| Physical presence/power properties | Software touch-down/up, hold durations, approval and power-cycle fixtures | A physical touch sensor and real electrical power/timing are outside a software-only emulator. Report the observable model and measure deviations; do not claim a hardware button. |
| Manufacturer attestation and secure-element trust | Own software identity, own issuer certificates, cryptographic signatures and storage model | Manufacturer private keys, certified attestation roots, secure-element unextractability and tamper resistance cannot be cloned. These are inherent differences; relying parties requiring certified hardware trust can reject the emulator. |
| Ambiguous or unmeasured individual protocol edges | Versioned matrix and candidate evidence, including an unpromoted PIV Printed-write candidate | Resolve with authoritative specification plus authorized read-only physical/differential observation or narrowly scoped interoperability testing. Keep uncertain status/precedence labelled as a model policy. |
| Long-running guest/kernel stability | No-NIC guest logs from each version, isolated FunctionFS fault probes | Re-run stressed USB guest on each transport change, preserve raw kernel warnings, compare frozen kernel/base image and exact binary hashes, and bound any flakiness. A retry does not erase an earlier failed run. |

The v0.64 staging run had an initial 12-marker USB guest failure after 10 zero exits, with a Linux workqueue warning, FunctionFS asynchronous transfer error, then HID/PCSC failures. The first raw log was preserved under `work/v64-integrated-guest/attempt1/` during integration. Check the final `../evidence/v64-integration/guest/` report and handoff before treating the v0.64 USB gate as passed. The build, private SDK and Python regression gates did pass independently. If the guest remains failing, keep v0.63 as the published release and hand off v0.64 as an incomplete candidate.

No work in this project changed the inserted physical key, host USB/HID/PCSC configuration, Keychain, keyboard or host kernel. Continue to use private software state and an owned no-network guest unless the user explicitly authorizes a wider test.
