# v61 isolated OATH SEND REMAINING candidate

Published v0.60.0 is copied into `baseline/`; `fixed/` changes only `emucard/core.py`. The baseline core SHA-256 is `f6587c70da88ca9f4e73779c49642471b3d0dbc84c58b84d6c26980404163a59`, identical to published v0.60.0 at the time of this audit. `source.patch` is the one-file integration patch.

Yubico's [YKOATH protocol, SEND REMAINING](https://developers.yubico.com/OATH/YKOATH_Protocol.html#send-remaining-instruction) specifies `CLA=00`, `INS=A5`, `P1=P2=00`. The [unmodified YubiKit OATH session](https://developers.yubico.com/yubikey-manager/API_Documentation/_modules/yubikit/oath.html) initializes its smartcard protocol with `INS_SEND_REMAINING`. Published v0.60 checks the common APDU CLA set but reaches its pending-response branch before enforcing `CLA=00` for OATH A5. A malformed `80 A5 00 00` therefore consumes the next 256 bytes of a segmented OATH response, leaving a subsequent valid A5 unable to reconstruct the original response. The one-line guard rejects the malformed CLA before changing the pending offset.

`verify_oath_remaining_cla.py` uses a fresh private CCID service or direct IFD fixture. It installs 24 TOTP credentials with stock YubiKit APDUs; stock `OathSession.list_credentials()` verifies a 504-byte response and normal continuation. It requests just one LIST byte, issues the malformed A5, then reads the remainder through valid A5 commands. The test independently decrypts the software state file to check that the malformed request does not mutate credential data. The baseline consumes 256 bytes and reports `61F7`; the candidate returns `6E00`, consumes zero bytes, and the valid continuation reconstructs all 504 bytes. This passed on macOS and in a `--network none --cap-drop ALL` Linux container, each through private CCID socket and direct IFD (4 A/B route pairs). The stock OATH regression passes 107/107 per route (428 total) and the broad smartcard regression passes 97/97 per route (388 total). Raw result JSON and hashes are in `results/` and `summary.json`.

The command and source evidence establish an internal software protocol mismatch with Yubico's documented CLA. They do not establish the exact rejection status, timing, or tolerant behavior of a physical YubiKey 5C Nano 5.7.4. `6E00` is the emulator's existing unsupported-CLA status. No physical key, host USB/HID/PCSC/Keychain, or network device was used; the direct IFD test loads the isolated bundle without registering a system reader.
