# v0.64 integrated release gate

`result.json` ties v0.64 source and Mac/Linux daemon hashes to the full regression. The main run passed 59 Python reports / 5,889 checks plus the Mac C++ suite (140 cases / 13,748 assertions), for 6,029 main checks. The independent Linux C++ suite passed the same 140/13,748 count, and unmodified Linux python-fido2 passed 82/82 via a private Unix socket. `build/` contains the exact CMake/Docker commands, 15 installed binary hashes and raw logs. `cards/` contains Mac/Linux private CCID socket/direct IFD HSM Auth, SCP03 and PIV Le results, including repeat IFD checks after rebuilding the drivers. `fido/` contains same-CID PING/WINK probes on the installed Mac/Linux daemons.

The owned no-NIC `dummy_hcd`/FunctionFS guest used a frozen base image and the v0.64 card modules/Linux binaries. Its **first** run completed only 10 of 12 zero-exit markers. A Linux `__queue_work` warning in the `usb_f_fs`/`dummy_hcd` completion path was followed by FunctionFS `EINPROGRESS`, HID `EIO` and fixture `BrokenPipeError`; `guest/attempt1/console.log` and `guest/attempt1/run.json` preserve that failure. The **second run of the identical guest image** completed all 12 markers with no warning, panic or traceback. The sealed `guest/result.json` records both attempts and all hashes. The gate passed on retry; guest transport stability and the first warning's root cause remain open. Do not describe the USB run as a clean first-pass success.

The tests use own fresh software credentials. They did not access the inserted physical key, host USB/HID/PCSC/Keychain, a production UDC, or a signed macOS composite device. The exact physical YubiKey 5C Nano 5.7.4 response and manufacturer trust remain unverified.
