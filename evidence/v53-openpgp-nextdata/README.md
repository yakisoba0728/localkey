# Isolated v53 OpenPGP GET NEXT DATA APDU validation

Base: published v0.52.0 `outputs/security-key-emulator/emucard/core.py`, SHA-256 `98c420ab0974feb08eb78735665045b4a39ceb5946b2dbf49d2c62b8f92cdc8e`. Candidate core SHA-256 `985d18c5d90c09621cc147b3c812b7ab0f3f7909f0e42a663231c5e84310c07a`. The only Python source change is `candidate/emucard/core.py`. `source.patch` SHA-256 `44ecf4cffd31c17256ee952a6d43c6a4ee66c2dcd9191216675cb513eb0a35e8`, and `patch --dry-run -p1` succeeds against the copied baseline.

The [OpenPGP Smart Card Application 3.4.1, §7.2.7](https://www.gnupg.org/ftp/specs/OpenPGP-smart-card-application-3.4.1.pdf) defines GET NEXT DATA (`INS CC`, `P1/P2=7F21`) with empty Lc and no command data. Published v0.52 accepts an extra data byte and advances the current certificate occurrence before reading. The candidate checks for empty command data before changing that pointer. `6700` is the emulator's rejection choice; exact physical YubiKey 5C Nano firmware 5.7.4 tolerance/status has not been measured. The SDK-compatible missing/zero Le forms remain unchanged.

`candidate/tools/verify_pgp_get_next_data_lc.py` creates two distinct X.509 certificates through unmodified YubiKit (`put_certificate` for AUT and DEC). It selects AUT, sends malformed `00 CC 7F 21 01 58 00` (ordinary short Le=00, but invalid Lc/data), then reads the currently selected certificate. On the published baseline the command returns certificate data with `61xx` and silently switches to DEC. With the candidate it returns empty data and `6700`; the current certificate remains AUT. Normal YubiKit certificate selection and a valid GET NEXT DATA still return the expected certificates. Both private CCID socket and direct IFD before/after reports are in `results/`.

Additional candidate regressions passed: OpenPGP extensions including all four certificate occurrences (private socket); OpenPGP objects/SDK crypto/state (119 checks each transport); previous GET DATA and GET RESPONSE command-chain guards (both transports); APDU headers (21 checks each transport). Thirteen JSON evidence reports all pass. Published outputs were read only; no physical key, host USB/HID/PCSC/Keychain, or OS reader was accessed.
