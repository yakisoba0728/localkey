# v56 PIV F9 key deletion candidate

Base: published v0.55 `outputs/security-key-emulator`. `emucard/core.py` SHA-256 `0d2404fb7d003ae2e3d22f82cbdcc1395672a4646f5b6587defd90471696723f`; `emucard/piv_objects.py` SHA-256 `6503c64561e904929d1aff05d127b9e1369f8a1961540f965ee00708c7b41664`. Isolated `source.patch` SHA-256 `3994b1a1563c98e754faefbf17c0957cd7f5a6ab328d5160f3c451fd098b45bd`. Published output and shared staging were not edited.

The [Yubico PIV extensions](https://developers.yubico.com/PIV/Introduction/Yubico_extensions.html) and [YubiKey Technical Manual](https://docs.yubico.com/hardware/yubikey/yk-tech-manual/yk5-apps-piv.html) agree: firmware 5.7 may **delete** the F9 attestation private key using `00 F6 FF F9`, while F9 may be neither the source nor destination of a **move**. The published emulator rejected both because the F9 source check preceded the delete/move branch. Its state initializer would also regenerate its own software F9 key on restart if the delete were simply enabled.

The patch permits the documented delete, keeps the move restriction, and records a deletion marker so that the emulator does not silently create a new software issuer on restart or PIV reset. A newly imported replacement F9 key remains usable and survives reset. The marker is local emulator bookkeeping, not a manufacturer credential or a claim about factory attestation trust. The saved F9 certificate is not deleted by this key-only command.

`results/before-socket.json` and `before-ifd.json` show unmodified YubiKit `PivSession.delete_key(SLOT.ATTESTATION)` rejected with `6A86`. `results/after-socket.json` and `after-ifd.json` show SDK deletion succeeds, F9 metadata and attestation fail while the key is absent, absence persists across process restart and PIV reset, moving F9 still fails, and ordinary SDK key move/delete remains functional. Before deletion, an SDK-generated PIV attestation statement's signature was independently verified against the emulator's own F9 certificate. After deletion, importing a replacement F9 key and retaining it across reset was checked through the SDK.

Candidate regressions passed: whole smart-card/private CCID socket and direct IFD suites (97 checks each), PIV profile socket/IFD (60 checks each), PIV object storage (31), and PIV certificate boundary (12). The focused test and regressions use fresh software cards, private Unix CCID sockets, and a direct IFD ABI; no host PC/SC, Keychain, physical key, or USB/HID was accessed.

The exact YubiKey 5C Nano firmware 5.7.4 status words, post-delete certificate visibility, and F9 state after a physical reset were not measured. The post-delete lifecycle follows the documented key-only deletion and nonrestorable original issuer behavior; it remains a software-model inference pending hardware differential testing.
