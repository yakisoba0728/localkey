# v0.59 isolated OpenPGP ACTIVATE FILE candidate

The copied v0.58 staging `emucard/core.py` baseline has SHA-256 `9342cf1bd73fa0435a08e10d4d6ca172287a15dd0f70cbedc1d062d09ea8d8df`. The isolated patch changes only the OpenPGP `INS 44` branch, applies cleanly to that baseline, and produces candidate core SHA-256 `e3894ba8b896611fcc67453783157db04e7875a344dcfa61f889b993a78d1f39`. `source.patch` SHA-256 is `a02a0c4a39ec57905e0d069aaec29e1800501512fac1d484d54482fd5ef6bf7f`.

Primary source: [OpenPGP Smart Card Application 3.4.1, §7.2.17 ACTIVATE FILE](https://gnupg.org/ftp/specs/OpenPGP-smart-card-application-3.4.1.pdf#page=78) specifies that an ACTIVATE FILE command in operational state ends with `9000` while leaving the application unchanged. In initialisation state after TERMINATE DF, it restores defaults. The copied v0.58 stage returned `6985` for the operational `00 44 00 00` command. The candidate returns `9000` without resetting the app, while preserving the terminated-state reset. The operational no-op runs before lazy OpenPGP attestation creation so even a pristine card remains semantically unchanged.

The same A/B test runs through four private paths: macOS CCID socket, macOS direct IFD ABI, Linux ARM64 CCID socket, and Linux ARM64 direct IFD ABI. In all four, the baseline gives `6985` and unmodified YubiKit `SmartCardProtocol.send_apdu(INS.ACTIVATE)` raises that APDU error; the candidate gives `9000` and the SDK call succeeds. A URL written by unmodified `OpenPgpSession` survives the command and process restart. Malformed P1 and Le remain rejected. A pristine card does not acquire an attestation key from this no-op. Unmodified `OpenPgpSession.reset()` still performs TERMINATE→ACTIVATE, removes the URL, and persists the reset after restart.

The card service encrypts and rewrites its state file on successful commands, so the successful no-op changes ciphertext bytes. The test decrypts both snapshots and proves semantic state equality; it separately verifies URL and pristine-key state after restart. See `results/{mac,linux}-{baseline,candidate}-{socket,ifd}.json` and `results/summary.json`.

Candidate regression per socket/IFD path: 97 smartcard checks, 119 OpenPGP object checks, and 21 APDU-header checks. OpenPGP extension checks passed 28/28 on macOS and Linux sockets. Linux ran in an ARM64 container with networking disabled, read-only source and no device passthrough; the Linux IFD ABI targeted only the private socket. These runs do not exercise Linux kernel USB/host PCSC. No physical key or host USB/PCSC/Keychain was accessed. Published outputs and shared staging were not modified.

The exact behavior and status-word tolerance of a physical YubiKey 5C Nano firmware 5.7.4 remains unmeasured. This candidate corrects the published OpenPGP 3.4.1 software behavior and unmodified SDK APDU result; it is not proof of full firmware equivalence.
